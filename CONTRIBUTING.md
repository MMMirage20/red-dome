# Как мы работаем

Правила для обоих участников команды «Красного купола». Коротко: задача — Issue, работа — в своей ветке, в `main` только через pull request с ревью второго участника и зелёным CI, в конце этапа — тег.

## Задачи и доска

- Каждая задача — Issue по шаблону «Задача»: ID из README или ТЗ этапа (например, `W3-10`), описание, критерии готовности.
- У Issue метка этапа: `stage-2` … `stage-6`.
- Доска GitHub Projects с колонками **Todo → In progress → Review → Done**. Взял задачу — перетащи в In progress; открыл PR — в Review; PR слит — Done.
- Ошибки заводим по шаблону «Ошибка»: как повторить, что ожидалось, что получилось.

## Ветки и коммиты

- Ветка от свежего `main`: `feature/<ID>-<кратко>`, например `feature/W3-10-score`.
- Коммиты небольшие и осмысленные, сообщение начинается с ID: `W3-10: очки по balance.score`.
- Каждый коммитит со своего аккаунта GitHub (почта в `git config user.email` привязана к аккаунту).

```bash
git switch main
git pull
git switch -c feature/W3-10-score
# ... работа, коммиты ...
git push -u origin feature/W3-10-score
```

## Pull request

- PR в `main` по шаблону: что сделано, как проверить, чек-лист.
- Ревью делает второй участник. Сливает автор после одобрения.
- `main` защищена: прямой push запрещён, слияние только после ревью и зелёного CI (workflow `tests`).
- В описании `Closes #номер` — Issue закроется сам.

## Этапы и теги

В конце этапа, когда все задачи этапа в Done и CI на `main` зелёный, ставим аннотированный тег на `main`:

| Этап | Тег |
| --- | --- |
| 1. Публикация MVP 1 | `v0.1-mvp1` |
| 2 | `v0.2-easy` |
| 3 | `v0.3-missions` |
| 4 | `v0.4-voice` |
| 5 | `v0.5-gestures` |
| 6 | `v0.6-heroes` |

```bash
git switch main
git pull
git tag -a v0.2-easy -m "Этап 2"
git push origin v0.2-easy
```

## Правила кода

1. Сначала читаем README, ТЗ и модули, которых касается задача. Если задача противоречит коду или README — обсуждаем, а не угадываем.
2. `reddome/sim` не импортирует pygame и детерминирован: случайность только через генератор от seed, без `time.time()` и глобального `random`. Одинаковый seed и одинаковые команды дают одинаковую партию.
3. Все числа баланса — в `reddome/config/balance.json` или новых `config/*.json`. В коде нет «магических» чисел.
4. Любой ввод (клавиша, кнопка, жест, голос) вызывает один и тот же метод `GameScene`. Новую команду сначала делаем методом, потом привязываем к вводу.
5. Графика только процедурная, через `reddome/render`. Текст интерфейса — на русском.
6. Перед работой и перед PR запускаем `pytest`. Старые тесты проходят, новая логика покрыта новыми. Тесты, которым нужны камера, микрофон, mediapipe, cv2, vosk или файлы моделей, пропускаются (`pytest.importorskip`, `pytest.skip`), если этого нет.
7. Новые зависимости — только с обоснованием в PR. Базовые — в `requirements.txt`, всё для ИИ-ввода — в `requirements-ai.txt`. Игра обязана запускаться без пакетов из `requirements-ai.txt`.

## Что не коммитим

- Модели: `models/gesture_recognizer.task`, `models/vosk/` — их качает `python tools/download_models.py`.
- Логи и датасеты: `ml/data/*.csv`.
- `.venv/`, `.vscode/`, сборки PyInstaller и другие крупные бинарники.

Всё это уже в `.gitignore`. Перед коммитом полезно посмотреть `git status`.

## Сторонние ресурсы

Библиотеку, шрифт, звук или картинку не нашего авторства сначала записываем в таблицу лицензий в README (лицензия и ссылка на официальный источник) и только потом добавляем в игру.
